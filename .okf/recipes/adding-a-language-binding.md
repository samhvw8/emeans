# When to use the C API

Python, Node.js and Go already exist ([language bindings](/design/bindings.md)); WebAssembly has
its own package. For any other language, wrap the C API ([C API](/design/c-api.md)) through that
language's C FFI. Do not write a new Rust crate per language unless the language needs one (as
PyO3 and napi-rs did): the C API keeps one ABI to maintain.

The [Go binding](/design/bindings.md) (`bindings/go/emeans.go`, `config.go`) is the reference: it
uses every rule below, and its tests are the model for a new binding's tests.[^go]

# Steps

1. **Get the library.** `mise run c:dist` writes `dist/` with `libemeans.a`, the shared library
   (`libemeans.dylib`, `libemeans.so.1`), `emeans.h`, `emeans.pc` and the CMake package. Load the
   shared library from the FFI, or link the static one when the language builds native code (Zig,
   Swift packages, Rust-free C extensions).
2. **Check the ABI first.** At load time, call `emeans_abi_version()` and refuse to run when it
   differs from the `EMEANS_ABI_VERSION` your binding was written for.[^header]
3. **Declare the functions** from `emeans.h`. Every fallible call returns `int32_t`; handles are
   opaque pointers (`EmeansModel*`, `EmeansHierarchy*`, `EmeansResult*`); `EmeansArray` is a
   `{const void *data; size_t len; int32_t dtype}` struct returned through an out-pointer.
   Generators save typing where the language has one (Dart `ffigen`, Zig `@cImport`, Swift module
   maps, Java `jextract`, C# `ClangSharp`); hand-written declarations are fine at this size (about
   30 functions).
4. **Wrap errors.** After a non-zero status, read `emeans_last_error()` at once, on the same OS
   thread, before any await, yield or blocking call. Map the code to the language's error type:
   `EMEANS_INVALID_ARGUMENT` (1) to an argument error, `EMEANS_ERROR` (2) to the library's error,
   `EMEANS_PANIC` (3) to an internal error. On failure the library writes no out-pointer, so
   there is nothing to free.
5. **Wrap ownership.** Every handle and result gets exactly one free call, with a safety net:
6. **Pass data without copies** where the language allows it (table below).
7. **Copy results out** into the language's own arrays (`emeans_result_array`, then copy `len`
   elements of `dtype`), then free the result. Read scalars from `emeans_result_json` (a JSON
   object) with the language's JSON parser. Copying out once is cheap next to the compute and
   makes the result's lifetime the language's problem, not the caller's.
8. **Configs.** Take a native map or struct, serialize it to JSON, pass it as `config_json`.
   Unknown keys come back as `EMEANS_ERROR` naming the key. For typed config structs, decode
   `emeans_default_config(kind)` into them with unknown fields refused, and test that the
   defaults go back through a call without an error: that catches a renamed key in both
   directions (the Go tests do this).
9. **Add the equality test** (below) and a quickstart, then document the binding.

| Rule | Why |
|---|---|
| Read the error on the calling thread, at once | `emeans_last_error` is thread-local and cleared by the thread's next emeans call |
| Free each handle once; NULL frees are no-ops | double free is undefined behavior |
| Keep input data alive and unchanged during a call | the library reads it in place; it never keeps the pointer after the call returns |
| Never run `emeans_hierarchy_add` beside another use of the same hierarchy | it changes the hierarchy; every other function only reads |
| A model can be shared by threads | it is read-only after training; assigns on it run one at a time inside |
| Treat views (`EmeansArray`, `emeans_result_json`) as borrowed | they die with their result or model |

# Per language

| Language | Load and declare | Free (safety net) | Data in without a copy | Watch out |
|---|---|---|---|---|
| Ruby | `ffi` gem: `ffi_lib`, `attach_function` | `FFI::AutoPointer` with the free function | not from Ruby arrays: pack them once into an `FFI::MemoryPointer` (`put_array_of_float`) and reuse that buffer across calls | the GVL keeps the error read on the same thread; release it only with a native extension |
| Java 22+ | Panama FFM (`java.lang.foreign`): `Linker.nativeLinker().downcallHandle`, `SymbolLookup.libraryLookup`; or JNA on older JDKs | `Arena` for inputs, `Cleaner` (or a confined arena's close) for handles | data in an off-heap `MemorySegment` (or a direct `FloatBuffer`) is passed as is; a heap `float[]` needs `Linker.Option.critical(true)` for in-place access, else a copy | a virtual thread does not move to another carrier between two downcalls with no blocking call between them, so read the error right away |
| C# (.NET 7+) | `[LibraryImport]` (source-generated P/Invoke), `NativeLibrary.Load` | `SafeHandle` subclasses that call the free functions | `fixed (float* p = span)` or `Span<float>` marshalled as a pointer pins without a copy | after an `await` the code may run on another thread: read the error before awaiting |
| Swift | a `systemLibrary` target with a module map over `emeans.h`, or a SwiftPM binary target | a `final class` whose `deinit` frees the handle | `array.withUnsafeBufferPointer { ... }` passes the array's storage | handles inside `Sendable` types need the threading rules above |
| Zig | `@cImport(@cInclude("emeans.h"))`, link `libemeans.a` and the `Libs.private` system libraries | `defer emeans_model_free(m);` | slices: `x.ptr`, `x.len / d` | none beyond C's |
| Dart | `dart:ffi` + `package:ffigen` from `emeans.h`, `DynamicLibrary.open` | `NativeFinalizer` attached to a wrapper object | `Float32List.address` in a `@Native(isLeaf: true)` call passes it in place (Dart 3.5+); else `malloc` + copy | leaf calls must be short: use them for `assign` on small batches, a normal call (with a copy) for `train` |
| Lua | LuaJIT `ffi.cdef` + `ffi.load`; PUC Lua needs a small C module | `ffi.gc(handle, lib.emeans_model_free)` / `__gc` | LuaJIT `ffi.new("float[?]", n * d)` arrays are passed in place; Lua tables must be copied | none beyond C's |

This table is written from general knowledge of each FFI; it was not checked against each
language's current documentation or tried in code. Check the versions and APIs when you start a
binding.

# The equality check every binding must pass

A binding passes when its results are byte-identical to the Rust facade on the same machine:

1. Write the fixture: `cargo run --release -p emeans-bindings-common --example write_fixture --
   DIR` (or `mise run bind:fixture`, which writes `target/bindings-fixture`). It holds synthetic
   data (`x.f32`, 1143 x 16, with near-duplicate bursts), `created.f64`, `priority.f32`, the
   configs as JSON overrides in `fixture.json`, and the facade's raw outputs.[^fixture]
2. In the binding's test, read `x.f32` into the language's own float array and run, with the
   fixture's configs: `train` (k 8) → compare `train.centroids.f32`, `train.labels.i32`, the
   per-epoch `obj` values and `objective` (the last epoch's moving mean) exactly with
   `fixture.json`, check `exact_objective` is absent, then train again with
   `exact_objective: true` → the same centroids and `exact_objective` equal to the fixture's; `assign` with the trained centroids and
   `inner_product` → `assign.labels.u32`, `assign.scores.f32`; `auto_cluster` on the first `n0`
   rows → `auto.{l1,l2}.u32`, `auto.{sim1,sim}.f32`, `auto.outlier.u8`; save and load (file and
   bytes), then `add` all rows → `add.*`, and the same `add` on the original hierarchy; `dedup`
   with `created` and `priority` → `dedup.group_of`, `representatives`, `sizes` (`u32`),
   `nn_sim` (`f32`).
3. Compare bytes, not values with a tolerance. The fixture is written at test time on the same
   machine, because the CPU kernel differs by target (Accelerate on macOS, the fused kernel on
   x86-64).
4. Also test: an unknown config key fails with its name in the message; a wrong length fails as
   an argument error; a use after free/close is refused by the wrapper (not passed to C);
   inputs are passed in place (compare the address the wrapper hands to C with the array's own).
5. Wire it into a mise task like `bind:go:test` (`depends = ["bind:fixture"]`, then the
   language's test runner with `EMEANS_FIXTURE` set), and run it on macOS and Linux.

Then add the binding to the tables in `README.md` and [language bindings](/design/bindings.md),
with a README of its own (install, a 10-line example, backends, limits) and a quickstart task
(`example:<lang>`).
